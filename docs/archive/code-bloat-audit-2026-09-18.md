# 代码体积与结构审计

日期：2026-09-18。代码基线：`8f3b9e8ae711`。本轮只审计并记录结论，没有修改业务代码、依赖或 UI。审计期间其他窗口对热力图样式、模型接口及视频页等文件进行了修改，本轮未触碰；以下数量和产物数据对应审计采样时的工作区，不代表其他窗口后续版本。

## 结论

项目确实存在可治理的臃肿，主要集中在全局样式反复覆盖、公共模块混入业务、迁移后的旧代码残留和首页提前加载。问题不是所有大文件都需要重写，也没有证据支持“大部分代码都可以删除”。

建议先清理确认无入口的代码和局部重复，再处理支付弹窗加载及组件职责，最后分批整理样式和语言资源。代码行数减少与浏览器加载量减少是两种不同收益。

| 位置                            | 规模 / 实测                        | 主要问题                                                         |
| ------------------------------- | ---------------------------------- | ---------------------------------------------------------------- |
| `src/styles.css`                | 21,982 行，占源码 CSS 行数约 45.4% | 页面与组件样式集中、同选择器多次覆盖                             |
| `src/components/common.tsx`     | 5,415 行                           | 登录、账户设置、布局、模型卡片、客服等混在同一模块，并有循环依赖 |
| `src/pages/console-account.tsx` | 2,545 行                           | `ApiKeysPage` 单组件约 1,949 行，列表、表单、权限、批量操作耦合  |
| `src/pages/trae-enterprise.tsx` | 2,210 行                           | 复杂业务与废弃表单、示例数据、未使用工具混存                     |
| 首页静态 JS 依赖链              | gzip 440.9 KiB                     | 超过项目 440 KiB 预算，支付与完整语言资源提前加载                |
| 当前生产无入口模块              | 3 个，共 610 行                    | 仅剩自身测试引用；另有相关残留样式                               |

源码还包含 153 个测试文件、约 2.5 万行测试，以及 9 个 i18n 文件、约 7,525 行资源定义。这些不能整体算作冗余业务代码。

## 具体发现

### B01：全局 CSS 的主要负担是所有权和覆盖顺序

`src/main.tsx:13` 无条件引入全局样式。虽然项目已经有 101 个 CSS 文件，`src/styles.css` 仍有 3,697 条规则、12,143 条声明和 138 个 `!important`，并保留密钥、账单、登录等页面样式。

在同一组外层 at-rule 条件下，全局文件有 134 个重复出现的选择器。例如：

- `.login-card`：`src/styles.css:1691`、`:5752`、`:19747`。
- `.login-popover`：`:4647`、`:13127`、`:19698`。
- `.recharge-options`：`:9936`、`:10553`、`:10719`。
- `.billing-filter-grid`：`:9695` 与 `:10302` 的声明完全相同。
- `src/mobile-home.css:470` 与 `:1625` 起的资讯卡片样式存在成组重复。

精确比较选择器、外层条件和有序声明，全部 CSS 中发现 16 组完全重复规则，合计 17 条额外副本；其中全局文件 6 条、`mobile-home.css` 11 条。这个数字只是精确重复的下限，不代表其余覆盖都无效，也不说明 CSS 大部分可以删除。

**建议：** 按登录、账单、密钥等实际组件归属逐块归并，保留最终计算样式。后来重复的规则可能用于恢复被中间规则覆盖的属性，不能直接按文本去重。先建立对应页面浅色、深色、桌面、手机的截图基线，再调整顺序与导入位置。仅拆成多个文件但仍全部由 `main.tsx` 引入，不会降低加载体积。

### B02：`common.tsx` 已成为跨业务大模块，并形成循环依赖

该文件同时包含 `PageTitle`（331 行起）、`ModelCard`（628）、`LoginPanel`（1193）、`PublicHeader`（1937）、账户设置弹窗（3471）、控制台布局（4091）、客服组件（4640）、公开布局（5245）。

确认的依赖环：

```text
common.tsx → header-purchase.tsx → common.tsx（LoginDialog）
common.tsx → header-purchase.tsx → purchase-hover-menu.tsx → common.tsx（客服事件）
```

其中客服入口只需要 `common.tsx:4477` 附近的事件函数，却依赖整个公共组件模块。循环依赖目前不等于已发生运行错误，但会增加初始化顺序、独立测试和拆包的难度。

**建议：** 先独立客服事件与其他轻量通信逻辑，再依次拆出登录、账户设置、公共布局和基础展示组件。搬迁期间可保留兼容导出，但新模块不能反向依赖旧聚合文件形成新的环。保留登录请求归属、通知版本、资料更新广播、退出动画及草稿阻塞逻辑。

### B03：首页加载了暂时用不到的支付功能，已有可量化收益

依赖链为 `common.tsx:162 → HeaderPurchase → header-purchase.tsx:12 → PurchasePaymentModal → PaymentQRCode → qrcode`。支付弹窗即使处于关闭状态，静态导入仍把相关代码带入首页。

仅对支付弹窗入口做内存中的条件懒加载转换并重新构建，没有改仓库源码，结果为：

| 对照                   | 首页 JS gzip | 相对基线               |
| ---------------------- | ------------ | ---------------------- |
| 当前源码               | 440.9 KiB    | —                      |
| 支付弹窗按打开条件加载 | 416.6 KiB    | 减少 24.3 KiB，约 5.5% |

CSS 同时减少约 2.2 KiB gzip。这是本轮最明确的加载优化机会，正式实现仍需处理首次加载状态，并回归未登录选套餐、登录后续购、个人与企业主体切换、关单、支付确认及关闭动画。对照构建不是已经交付并验证过的补丁。

### B04：存在可确认的源码残留，但收益需要分别计算

通过源码引用、静态与动态导入图、生产模块图三种方式交叉检查，以下模块当前没有生产入口：

| 模块                                             | 源码行数 | 当前引用   |
| ------------------------------------------------ | -------- | ---------- |
| `src/components/analytics-time-range-picker.tsx` | 460      | 仅自身测试 |
| `src/components/trae-usage-department-table.tsx` | 125      | 仅自身测试 |
| `src/utils/invitation.ts`                        | 25       | 仅自身测试 |

对应测试共 206 行。部门表格还有 72 行专属 CSS；旧时间选择器在 `src/styles.css:19453–19685` 留有约 233 行全局样式，相关类名只在这个无入口组件中使用。

这三个模块已经不在生产 JS 产物中，清理不会进一步减少首页 JS；全局残留 CSS 则仍会随页面加载。应把组件、专属测试、专属样式作为一组清理，先确认没有计划保留的入口。

企业页还有更直接的迁移残留：

- `trae-enterprise.tsx:1447` 的弹窗状态允许 `"member"`，但全部状态写入只有 `"rules"` 和 `null`；`:2001–2054` 的旧成员表单不可达。
- `:1578` 的旧 `submitMember` 仅关闭弹窗并提示成功，没有调用 API。该函数随不可达表单保留，不代表现有真实邀请功能失效。
- `:248` 的示例部门树、`:278` 的旧展平函数、`:444` 的 `TraeSection` 等没有使用者。

额外启用 TypeScript 的 `noUnusedLocals`、`noUnusedParameters` 后，有 51 条未使用诊断，其中 42 条来自非测试文件、9 条来自测试文件。包含未使用导入、局部变量、参数和私有函数，不能把每条都当成可直接删除的完整功能；例如删除一个未使用 state 值时仍需检查 setter 和副作用。

**建议：** 先清理私有未使用项、不可达旧表单、确认退役组件，再考虑清理公开导出。保留实际邀请链接、加入审批、规则设置和真实部门 CRUD。

### B05：密钥和充值页面的职责边界需要调整

`console-account.tsx:248–2196` 的 `ApiKeysPage` 集中处理列表分页、密钥全文展示、创建编辑、企业筛选和批量操作。`:690` 的表单转换同时控制字段错误、Toast 和请求参数；`:823`、`:884` 的单项与批量操作有重复限制映射。

**建议：** 先抽纯校验和请求转换，再拆受控的编辑弹窗与列表。保持现有 UI 和表单交互，特别保留“未修改 IP 白名单”与“主动清空”的区别、个人与企业管理权限、批量部分失败处理，以及关闭弹窗时清除完整密钥。

另一个边界问题在 `recharge.tsx:15`：充值页直接从账单页导入 `RechargeTab`、`PaymentReturnNotice` 和上下文工具。`billing.tsx:587–982` 的充值组件约 396 行，包含建单、恢复、轮询和关闭流程。

**建议：** 将充值组件和账务上下文移到明确的共用模块；沿用现有支付 hooks，保留账户作用域 key、幂等重试、响应丢失后的恢复、确认关单及支付结果处理。仅搬代码不承诺产生包体收益。

### B06：API 层有局部重复和已退役入口，应小范围收敛

- `user-api-keys.ts:265` 与 `:333` 的个人、企业全量分页循环，除页面加载函数外实现一致。可以保留两个业务入口，抽一个文件内分页辅助函数，避免以后修复只覆盖其中一份。
- `enterprise-usage.ts:129`、`:141`、`:158` 的三个旧查询入口只有测试引用；生产页面使用 `:175` 的 detail 入口。`enterprise-console.ts:896` 又提供同一 `/usage` 端点的实现，需统一后明确保留的入口。
- `personal-usage.ts:845`、`:945` 的旧概览与分析入口仅见测试使用，但文件注释提到外部页面消费者，退役前应确认外部契约。
- `auth-slice.ts:263` 起四种登录方式的 pending / fulfilled reducer 重复，可以用小型辅助函数或 matcher 收敛，优先级低于清理残留。

不要把所有分页抽成同一个工具：密钥分页遇到重复页时去重并终止，`personal-usage-models.ts` 的完整性校验会对重复或截断抛错，行为不同。密钥分页的 100 页上限、取消信号、缺省分页兼容和模型选项合并都需要保留。

同理，错误码优先级、版本字段兼容、金额与时间转换不应仅凭外观类似合并。登录 reducer 的整理必须保留 request ID 归属检查，不能重新引入登录竞态。

### B07：语言资源一次加载全部内容，适合后续专项优化

`main.tsx:11` 引入 i18n，`i18n/index.ts:3–9` 静态导入全部资源，并在初始化时注册中英文、公开页面、控制台及企业资源。9 个 i18n 源模块都进入首页依赖链。

临时移除英文资源的诊断对照使首页 JS gzip 从 440.9 降到 392.6 KiB，差值 48.3 KiB。这只能证明语言拆分存在较大的优化空间，**不能删除英文，也不能把该数值当作正式异步加载的确定收益**。

**建议：** 先按当前语言加载，再评估按业务拆分。确保首次访问 `/en`、语言切换、直接进入控制台或企业深层路由、API 错误文案都不会短暂显示翻译 key。不同构建对照的节省量不能直接相加。

### B08：仅确认一个多余直接依赖，不建议大规模替换技术栈

20 个直接生产依赖中，19 个进入生产模块图。`prismjs` 没有实际源码导入，生产模块图也没有该包；`src/prism-languages.ts:1` 使用的是 `prism-react-renderer` 自带 Prism。

**建议：** 删除未使用的直接 `prismjs` 依赖声明并更新锁文件，检查代码高亮。它原本不在浏览器产物中，因此浏览器 JS 节省为 0，收益是依赖维护简化。

已确认 Semi 按组件路径引入，ECharts 按 core / chart / component 导入；图表和 Markdown 都是延迟块。没有证据支持为了减重整体替换组件库或图表库。

## 不应为了减少行数而删除的内容

- 回归测试、翻译、接口类型和必要的运行时校验。大型 API 文件中相当一部分是类型定义。
- 登录请求隔离、晚到响应保护、幂等建单、关单确认、轮询边界和弱网恢复。这些已有明确业务用途。
- Sentry。关闭 DSN 的诊断对照确实减少约 26.8 KiB gzip，但会损失现有首屏监控能力，不属于无用依赖。
- `src/runtime/build-version-guard.js`。它不是常规 import 入口，但由 `vite.config.ts:43` 读取并注入 HTML；不能被未引用扫描误删。
- 不能根据产物文件名判断归属：名为 `app-toast` 的共享块包含 i18n、API、Sentry 等 146 个模块，并不等于 Toast 本身占用 155.1 KiB gzip。

## 本轮验证与边界

- 检查源码规模、引用关系、生产模块图、CSS 规则结构、局部重复和页面状态写入；动态 import 也纳入入口检查，并人工排除构建注入脚本。
- 使用 Node 26.5.0，以 production 模式生成隔离产物，关闭 Sentry 上传。**Vite 打包成功，现有体积门禁失败**：首页 JS gzip 440.9 KiB 超出 440 KiB 预算约 0.9 KiB。因此不能把这一结果称为完整 `npm run build:prod` 成功，也没有提高预算掩盖问题。
- 首页静态 CSS 为 657.1 KiB raw / 100.8 KiB gzip；图表块为 561.1 / 189.1 KiB，Markdown 块为 404.9 / 121.8 KiB，后两者不属于首页静态加载链。
- 体积统计遵循 `scripts/check-bundle-size.mjs`：遍历 `index.html` 和首页入口的静态依赖，对每个资源分别 gzip level 9 后求和；不含图片、第三方脚本和按需模块，不等于实际用户网络耗时。
- 未使用项检查通过 `tsc --project tsconfig.app.json --noEmit --incremental false --noUnusedLocals --noUnusedParameters --pretty false` 完成。51 条诊断来自额外开启的清理检查，不代表项目默认配置新增了这些报错。
- 对照构建仅在构建转换阶段临时调整支付导入、语言资源或监控配置，仓库源码未改；用于归因，不代替正式实现的行为测试。本轮未重新跑全量功能测试或浏览器 UI 回归，因为没有实施功能 / UI 修改。
- 一次性脚本、日志和构建均放在仓库外；本文记录可复核的源码位置、方法和结果，不依赖本机临时文件。
- 交付前尝试清理本轮两个系统临时目录，命令被自动审批策略以 `blocked by policy` 拒绝，未绕过限制；这些材料仍在系统临时目录，仓库中没有新增临时文件。
