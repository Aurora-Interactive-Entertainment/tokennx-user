## 基线与并发保护

- 从 HEAD `8f3b9e8ae711` 加当前工作区建立仓库外冻结快照，保留当时已有修改，而非只测试 Git 提交版本。
- 同时建立仅叠加本轮补丁的对照版本，用于前后包体和浏览器比较，避免把其他窗口的后续变化误判为本轮收益或回归。
- 使用 Node 26.5.0 / npm 12.0.1。所有测试使用相同的 `NODE_OPTIONS=--no-experimental-webstorage`，以避免 Node 原生 Web Storage 与 jsdom 测试存储冲突。
- 隔离快照复用项目依赖；测试配置只为共享依赖目录增加 Vite 文件读取白名单，解决 SVG 原始资源位于快照目录外的问题。未修改仓库测试配置或测试断言。
- 生产产物均输出到任务独立目录，关闭 Sentry 构建上传，没有覆盖项目 `dist` 或部署。

## 包体与已有问题

相同冻结源码，仅叠加本轮清理的对照结果：

| 指标                | 清理前             | 仅本轮清理后       |
| ------------------- | ------------------ | ------------------ |
| 首页 JS raw / gzip  | 1359.6 / 441.2 KiB | 1359.6 / 441.2 KiB |
| 首页 CSS raw / gzip | 657.1 / 100.8 KiB  | 652.1 / 100.0 KiB  |

本轮主要减少维护负担，并移除约 5 KiB 首页 CSS 原始体积。旧模块本来没有进入生产 JS，移除直接依赖声明也不会删除 Semi 仍需要的安装包，因此没有宣称这部分带来 JS 或安装体积收益。

最终工作区包含其他窗口后续视频等改动，最后打包测得首页 JS **441.1 KiB gzip**、CSS **99.8 KiB gzip**。其中全局视频样式的额外变化已保留，没有计入本轮 252 行 CSS 清理。

**首页 JS 仍超过既有 440 KiB 预算。** 这是基线已有问题，本轮没有提高预算或扩大到阶段 2。因此 Vite 打包成功、静态发布完整性通过，不等于完整生产构建门禁全部通过；体积问题按方案留给支付按需加载阶段。

8 个涉及的 TSX 文件在清理前后均存在原有 Prettier 格式告警。本轮保持原代码风格并通过差异空白检查，没有混入全文件格式化。
